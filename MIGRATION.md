# October 2026 generation migration

- Removed the `Prepare` executable and its `OrderedCollections` dependency. Make now downloads the public Discovery OpenAPI document without credentials, validates and sorts JSON in temporary files, and replaces the source spec only after success.
- Moved the Discovery source spec and overlay from `assets/` to `specifications/discovery/`. Added the official beta Interactions source and overlay under `specifications/interactions/`. Root `original_openapi.json` is now generated by composing those inputs, and the root overlay is intentionally empty. The old generator configuration is replaced by separate Types and Client configurations with idiomatic naming.
- Adopted the generator's four products: Types, core Client, URLSession, and AsyncHTTPClient. Consumers must import Types for `Components`, `Operations`, and `Servers`, and the relevant transport module for factories. `createClient(apiKey:timeout:)` now belongs to `GoogleGenerativeLanguageAsyncHTTPClient`.
- Replaced the legacy `AuthenticationMiddleware(apiKey:)` with shared operation-aware authentication. Use `.apiKey(...)` or `AuthenticationMiddleware(authentication: .apiKey(...))`. Missing required credentials now fail before transport.
- Removed the fixed `Part` union and its custom branch models. It lost new upstream fields, treated signatures/video metadata as mutually exclusive payloads, and collided with Google's new `FunctionResponsePart`. Use `.init(text: ...)` instead of `.TextPart(.init(text: ...))`; use `.init(fileData: .init(value1: ...))` for referenced payloads. Signatures and other metadata can accompany content.
- Removed the stale `ModelID` enum; use model ID strings supplied by the caller. Review upstream removals as well: the refreshed spec removes several old chunk/search schemas and adds batch, environment, and file-search APIs.
- Upload MIME types are unrestricted strings. `xGoogUploadHeaderContentType: .audioMpeg` becomes `xGoogUploadHeaderContentType: "audio/mpeg"`. The upload helper now forwards the caller's MIME type and byte count.
- Requires Swift 6.2+ because the resolved generator requires that toolchain. The migration used Swift 6.4.2, bootstrapper 0.3.0 at upstream commit `021134f`, and Swift OpenAPI Generator 1.14.3. The first run used the sibling checkout including its pre-existing uncommitted `op15_remove_fields` transformer; the final regeneration and idempotence check used the latest upstream tool through the default Make command. The sibling transformer changes were left untouched.

## Overlay ownership

API-key declarations, streaming content types, Google upload headers/paths, and output-only response requirements require provider knowledge. Keep these in the Google overlay. The Interactions source also needs explicit string types for its untyped constant tags; otherwise tagged-union responses can decode as incorrect branches. Scalar type inference in the const-to-enum transformer is a potential reusable improvement, handled explicitly in this provider overlay for now. A separate general Makefile bug was reproduced and fixed in the bootstrapper template: macOS GNU Make 3.81 ignores `.SHELLFLAGS`, so flags must be carried in `SHELL` to stop recipes on errors, failed pipelines, and unset variables. The download failure-path check now confirms that invalid specs leave the source unchanged and clean up temporary files. In particular, globally converting optional object properties into a `oneOf` would invent exclusivity and repeat the old `Part` problem.

Google's original file/cached-content operations include OAuth/bearer alternatives but omit the API-key option used by Gemini. The overlay appends API-key alternatives to existing security arrays and sets a root requirement for new/custom operations. It retains the upstream alternatives. Future regeneration should review any new security requirements rather than assuming the source's empty arrays are intentional public access.

Both factories preserve fractional-second dates, upload-header unescaping, and explicit configuration overrides. The AsyncHTTPClient default remains 20 minutes. Handwritten helpers live outside generated directories and survive reruns.

## Interactions and transcription

The Interactions source is Google's official [beta OpenAPI JSON](https://ai.google.dev/static/api/interactions.openapi.json), which complements the Discovery source. The stable v1 schema currently lacks the transcription configuration used by the beta transcription guide. Both source documents are checked in, downloaded independently without credentials, and transformed with their own overlays before composition.

`Client.transcribeAudio(fileURI:mimeType:configuration:model:)` calls `/v1beta/interactions` and defaults to `gemini-3.5-transcribe`. It returns the generated `InteractionsInteraction`, including typed word annotations; `outputText` and `wordAnnotations` provide convenient access. Raw `createInteraction` supports JSON and SSE, inline audio, and typed errors. Both APIs use the existing client/transport products; no additional product dependency is needed. Use the global endpoint for Interactions; Discovery's existing regional server remains available for its own APIs.

The merge script prefixes added component names and rewrites references/discriminator mappings. It prefixes only conflicting new operation IDs, preserving all existing API names. It retains each source's effective authentication requirements and deduplicates the conventional `GoogleAPIKey` and `bearer_auth` schemes. Conflicting paths, definitions, versions, or primary servers fail before replacing the combined input.

The Interactions overlay removes the closed `ModelOption` enum because Google's `x-speakeasy-unknown-values: allow` denotes an open enum and its list omits the documented transcription model. It maps custom Speakeasy authentication to standard header API-key/bearer alternatives, and gives `type`/`event_type` tags explicit string types after const normalization. These changes support encoding transcription requests and decoding the correct step, content, annotation, and SSE event branches.

## Validation

Run `make build` and `make test-offline`. Tests cover schema composition, local references, collisions, source authentication, existing generation/upload behavior, transcription settings, model strings, speaker/timing annotations, and JSON/SSE/error responses. Live tests remain opt-in and were not run.
